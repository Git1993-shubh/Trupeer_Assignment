================================================================================

  - Reuses Part 2 page objects
  - Generates detailed JSON reports
  - Location: part3/

5. RUNNING PART 2: E2E AUTOMATION TESTS
================================================================================

BASIC EXECUTION:

  cd part2

This runs all tests in headless mode (no browser window).

EXPECTED OUTPUT:

  10 passed in 3.5s
  
  Login Tests
    ✓ should login successfully and land on dashboard
    ✓ should display error on invalid login attempt
  
  Editor Tests
    ✓ should navigate to editor and display all key components
    ✓ should modify script using AI and display modified output
    ✓ should handle AI modification with different prompts
    ✓ should apply modified script if apply button is available
  
  Negative Tests
    ✓ should prevent AI script modification when prompt is empty
    ✓ should handle network/server errors gracefully
    ✓ should handle missing video gracefully
    ✓ should maintain session after navigation

ADVANCED EXECUTION OPTIONS:

1. RUN TESTS IN HEADED MODE (see browser):
   npm run test:headed

2. DEBUG MODE (step through tests):
   npm run test:debug

3. RUN SPECIFIC TEST FILE:
   npm test -- tests/login.spec.js
   npm test -- tests/editor.spec.js
   npm test -- tests/negative.spec.js

4. RUN SPECIFIC TEST BY NAME:
   npm test -- -g "should login successfully"

5. RUN ON SPECIFIC BROWSER:
   npm run test:chrome       # Chromium only
   npm run test:firefox      # Firefox only (install first)
   npm run test:webkit       # Safari only (install first)

6. VIEW TEST RESULTS:
   npm run report

   Opens Playwright HTML reporter showing:
   - Test timeline
   - Screenshots on failure
   - Video recordings on failure
   - Detailed error traces
   - Timing information

TEST CONFIGURATION:

File: playwright.config.js
  - Base URL: from TRUPEER_BASE_URL env var
  - Timeout: 30 seconds per test
  - Expect timeout: 5 seconds per assertion
  - Retries: 0 locally, 2 on CI
  - Screenshot: captured on failure
  - Video: captured on failure
  - Trace: captured on first retry

9. IMPORTANT NOTES ON SELECTORS
================================================================================

SELECTOR STRATEGY:

Page objects use this priority:
  1. getByRole() - Most stable (accessibility)
  2. getByLabel() - Form labels
  3. getByPlaceholder() - Input placeholders
  4. getByTestId() - data-testid attributes
  5. Stable CSS selectors - Last resort

SELECTOR VERIFICATION NEEDED:

Some selectors are based on common UI patterns and may need adjustment for
actual Trupeer UI. If tests fail with "locator not found" errors:

  1. Run in headed mode: npm run test:headed
  2. Use browser DevTools to inspect the actual element
  3. Update the selector in the page object
  4. Run tests again to verify

FILES TO UPDATE:
  - part2/pages/LoginPage.js
  - part2/pages/DashboardPage.js
  - part2/pages/EditorPage.js

EXAMPLE SELECTOR ADJUSTMENT:

If email input selector fails:
  Before: page.locator('input[type="email"]')
  After: page.locator('input[name="email"]') or page.getByPlaceholder('Email')

10. TROUBLESHOOTING
================================================================================

ISSUE: "Missing required environment variables"
SOLUTION:
  1. Create .env file in root directory
  2. Copy values from .env.example
  3. Fill in your Trupeer credentials
  4. Verify file location: c:\Users\Shreya Shrivastava\Trupeer_Assignment\.env

ISSUE: "Timeout waiting for login"
SOLUTION:
  1. Verify TRUPEER_BASE_URL is correct (should be https://app.trupeer.ai)
  2. Check internet connection
  3. Verify credentials are correct
  4. Verify Trupeer is online
  5. Check selector is valid for actual UI

ISSUE: "Locator.waitFor: Timeout waiting for selector"
SOLUTION:
  1. Run test in headed mode: npm run test:headed
  2. Inspect element with browser DevTools
  3. Verify selector matches actual element
  4. Update selector in page object
  5. Rerun test

ISSUE: "OpenAI API error: Invalid authentication"
SOLUTION (Part 3):
  1. Verify LLM_API_KEY in .env is correct
  2. Check API key at https://platform.openai.com/api-keys
  3. Ensure account has usage quota/credits
  4. Key may have expired - regenerate if needed

ISSUE: "Rate limit exceeded"
SOLUTION (Part 3):
  1. Wait 1 minute before retrying
  2. Use gpt-3.5-turbo instead of gpt-4 (cheaper)
  3. Run validation less frequently

ISSUE: "Element not visible" or "Button not clickable"
SOLUTION:
  1. Element may be covered by modal/overlay
  2. Scroll to element: await locator.scrollIntoViewIfNeeded()
  3. Wait longer: increase timeout in playwright.config.js
  4. Try in headed mode to see actual state

12. CI/CD INTEGRATION
================================================================================

For continuous integration (GitHub Actions, Jenkins, etc.):

GITHUB ACTIONS EXAMPLE:

  name: Trupeer QA Tests
  on: [push, pull_request]
  
  jobs:
    test:
      runs-on: ubuntu-latest
      steps:
        - uses: actions/checkout@v3
        - uses: actions/setup-node@v3
          with:
            node-version: '18'
        
        - name: Install dependencies
          run: |
            cd part2
            npm install
            npx playwright install
        
        - name: Run tests
          run: |
            cd part2
            npm test
          env:
            TRUPEER_EMAIL: ${{ secrets.TRUPEER_EMAIL }}
            TRUPEER_PASSWORD: ${{ secrets.TRUPEER_PASSWORD }}
            TRUPEER_BASE_URL: https://app.trupeer.ai
            TRUPEER_VIDEO_NAME: test-video
        
        - name: Upload results
          if: always()
          uses: actions/upload-artifact@v3
          with:
            name: playwright-report
            path: part2/playwright-report/
            retention-days: 30

ENVIRONMENT VARIABLES IN CI:
  - Store secrets in GitHub Secrets/AWS Secrets Manager
  - Pass to tests via env: block
  - Never commit .env or credentials
  - Use different credentials for CI if possible

13. KEY ASSUMPTIONS & LIMITATIONS
================================================================================

ASSUMPTIONS:
  ✓ Trupeer URL is https://app.trupeer.ai
  ✓ Login uses email/password (not OAuth)
  ✓ "Modify Script with AI" feature exists in editor
  ✓ User has at least one video in account
  ✓ OpenAI GPT-4 available (Part 3)
  ✓ Selectors match common UI patterns

KNOWN LIMITATIONS:
  - AI output is nondeterministic (tests verify properties, not exact text)
  - Single account testing (can't test multiple users simultaneously)
  - Rate limiting possible on heavy usage
  - Some selectors may need adjustment for actual Trupeer UI
  - LLM evaluation works best for English content

WORKING AROUND LIMITATIONS:
  1. Selector issues → Inspect DOM and update page objects
  2. Flaky tests → Use explicit waits, avoid arbitrary sleeps
  3. Rate limiting → Add backoff retry logic
  4. AI nondeterminism → Evaluate properties, not exact content

14. MAINTENANCE & UPDATES
================================================================================

WHEN TRUPEER UI CHANGES:

  1. Run test in headed mode: npm run test:headed
  2. Identify which test fails
  3. Inspect element with DevTools
  4. Find updated selector
  5. Update page object (part2/pages/*)
  6. Verify test passes
  7. Part 3 automatically inherits the fix

WHEN ADDING NEW TESTS:

  1. Create new file: part2/tests/feature.spec.js
  2. Import required page objects
  3. Write test using existing methods
  4. Run test: npm test -- tests/feature.spec.js
  5. Verify passes

WHEN ADDING NEW PAGE OBJECT:

  1. Create file: part2/pages/NewPage.js
  2. Define selectors and methods
